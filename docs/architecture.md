# Архитектура EventHub

## Доменные сценарии

1. Участник находит событие через фильтры.
2. Открывает динамический маршрут `/events/:id`.
3. Регистрируется и получает билет.
4. Добавляет события в расписание.
5. Сотрудник площадки подтверждает вход по коду.
6. Организатор видит метрики и создаёт события.

## Технические решения

- `withComponentInputBinding()` связывает route params с `input()` без ручной подписки.
- `EventStore` инкапсулирует команды и вычисляемые селекторы.
- Переиспользуемый `EventCardComponent` отделяет карточку каталога от страницы.
- CSS-постеры заменяют внешние изображения и сохраняют автономность проекта.

## Production roadmap

REST/GraphQL API, OAuth, платёжный провайдер, email/QR генерация, real-time остатки мест, роли и guards, SSR для SEO, i18n, Playwright и CI/CD.
